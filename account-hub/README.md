# SYHU Account Hub

A private, local-first manager for your whole digital ecosystem: platforms, accounts, reusable email identities, YouTube channels, artists and labels, projects, developer and gaming accounts, banking metadata, subscriptions and an encrypted vault.

Developed by **SYHU LABS**. One Flutter codebase targets **macOS** (primary), **iOS**, **Android**, and Linux desktop.

> No online account, no cloud, no telemetry. Everything lives in a single SQLite database on your device. Secrets are AES-GCM encrypted with a key kept in the OS keychain.

## Why Flutter and not SwiftUI

The brief asked for a native macOS app *and* iOS *and* Android. SwiftUI cannot ship Android, so the project is built with Flutter: one Dart codebase, native build outputs for every target (`.app`, `.ipa`, `.apk`), platform services through first-party plugins (Keychain / Keystore, Touch ID / Face ID / biometrics, local notifications, file dialogs). The shared business logic (`lib/domain`, `lib/data`) is pure Dart and is covered by tests that run on any OS.

## Getting started

```bash
cd account-hub
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # regenerates drift code if you change tables
flutter run -d macos      # or: -d ios, -d android, -d linux
```

macOS and iOS are also built on every push by the GitHub Actions workflow in `.github/workflows/apple-builds.yml` (artifacts on the run page). See `docs/BUILD.md` for per-platform requirements and `docs/ARCHITECTURE.md` for the design. `docs/PROGRESS.md` is the feature-completion checklist and verification record.

## Plan prices by country and store

Settings → Profile sets your **country** (29 markets) and the **store you usually subscribe through** (web, App Store, Google Play). The subscription form's *Choose a plan* button and the *Plans in <country>* card on every platform page quote the service's published plans for that combination, falling back to the country's web price and then to the service's default (USD) price, and say which one you are seeing. Prices live in `assets/catalog/plans.json` with a source URL and verification date per number and are never fetched live; `docs/PLANS.md` documents the format and the update script.

## Logos

`assets/logos/` holds coloured original marks for 1137 of the 1227 catalog platforms, gathered by `tool/fetch_logos.py` and `tool/fetch_appstore_icons.py` from LobeHub's AI icon set, homarr dashboard-icons, gilbarbara/logos, svgl, the brands' own website icons and official App Store artwork. Every file is the brand's published mark rasterised to 128px; nothing is redrawn. `docs/LOGO_SOURCES.md` lists the source URL per file and `manifest.json` records each mark's tone so dark marks get a light tile in dark mode.

Resolution order in the app: `assets/logos/<platform-id>.png|svg` → Simple Icons glyph tinted with the brand colour → monogram tile. Drop any further originals into `assets/logos/` named by catalog id and they are picked up on the next build.

## Security notes

- Vault payloads: AES-256-GCM, per-item random nonce, item id bound as associated data, master key stored only in Keychain / Keystore / libsecret.
- Encrypted backups: PBKDF2-HMAC-SHA256 (600k iterations) → AES-256-GCM.
- Plain backups and CSV / JSON exports never include vault items.
- Global search, notifications, audit log and toasts never contain secret values.
- App Lock uses the platform's biometric / system authentication where available, with a salted passcode fallback. Auto-locks after inactivity and when backgrounded.
- This application has **not** been independently security-audited.
